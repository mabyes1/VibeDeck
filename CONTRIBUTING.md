# Contributing to VibeDeck

Thanks for taking the time to help make VibeDeck better.

## Issues are the best place to start

Bug reports, device compatibility notes, usability problems, and feature ideas are welcome through GitHub Issues.

When reporting a bug, please include the device/browser involved, what you expected to happen, what actually happened, and any useful screenshots or logs that do not contain private credentials.

## Pull requests

VibeDeck is currently maintained primarily through direct project development rather than an open contribution queue. Unsolicited pull requests may be closed even when the idea is useful, especially when they overlap with active product work or change architecture, packaging, security, pairing, or device behavior.

If you have an implementation idea, opening an Issue first is the most useful way to discuss it.

Small documentation corrections may still be accepted when they are straightforward and do not change product behavior.

## Security reports

Please do not publish credentials, pairing tokens, tunnel secrets, API keys, or other sensitive data in a public Issue. For security-sensitive findings, use GitHub's private vulnerability reporting feature when it is available for the repository.
